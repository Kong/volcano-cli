# Volcano Next.js Demo

Generated by `volcano init nextjs --example notes`.

## What was created

- `../package.json` for shared web/function dependencies (`@volcano.dev/sdk`, Next.js, React).
- `../volcano/migrations/` with a per-user notes table and RLS policies, one SQL statement per file.
- `../volcano/_shared/volcano-client.js` shared Volcano client helper used by both web and function code.
- `../volcano/functions/notes-summary.js` to demonstrate authenticated function invocation.
- `../volcano/volcano-config.yaml` so signed-in users can invoke `notes-summary`, and so the web app is built with the variables it needs.
- `../.volcano/source-layout.json`, which tells `volcano deploy` (and a connected Git repository) to deploy this app as the `web` frontend.
- `./next.config.js` to allow importing shared code from outside `web/`.
- A minimal Next.js app with signup/signin and per-user notes dashboard.

## Quickstart (Local)

Run commands from the project root.

1. Start local Volcano: `volcano start`
2. Deploy everything: `volcano deploy --with-migrations`
3. Open the `web` URL the deploy prints

`volcano deploy` saves the variables, applies the migrations, deploys the
function and the frontend, then applies the project configuration. Migrations
run again on every `--with-migrations` run; these are safe to repeat.

To edit with hot reload, run `npm install` and `npm run dev`, then open
[http://localhost:3000](http://localhost:3000).

The same steps one at a time:

```bash
volcano variables deploy
volcano migrations deploy --all -d app
volcano functions deploy --all
volcano frontends deploy --name web --path . --app-root web --variable-scope scoped \
  --variable NEXT_PUBLIC_VOLCANO_API_URL --variable NEXT_PUBLIC_VOLCANO_ANON_KEY \
  --variable NEXT_PUBLIC_VOLCANO_DATABASE
volcano config deploy
```

## Cloud

```bash
volcano login
volcano use <project-id-or-name>
volcano cloud deploy --env-file volcano/cloud.env --with-migrations -d <database>
```

`volcano/volcano.env` holds the local server's values. Put the cloud project's
values in another file, such as `volcano/cloud.env`, under both sets of names:
`VOLCANO_API_URL`, `VOLCANO_ANON_KEY`, and `VOLCANO_DATABASE` for the
function, and the same values as `NEXT_PUBLIC_VOLCANO_API_URL`,
`NEXT_PUBLIC_VOLCANO_ANON_KEY`, and `NEXT_PUBLIC_VOLCANO_DATABASE` for the web
app. Frontend builds never see `VOLCANO_*` names. The root `.gitignore` keeps
`volcano/*.env` out of Git, and frontend uploads always leave them out.
`volcano cloud deploy` refuses `volcano/volcano.env`, since its URL and keys
only work locally.
